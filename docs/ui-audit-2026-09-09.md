# UI audit — 9 September 2026

## Verdict

The shared UI is materially improved, but the entire application is **not yet signed off as production-polished**. This pass combines an application-wide source inventory with targeted browser testing and local fixes. It is not a certification of every workflow, tenant theme, or accessibility requirement.

No backend records, product areas, stock, prices, or transaction histories were changed. Nothing was deployed.

## Coverage and evidence

- Source inventory: **90 route files**, 114 TSX files, 26 tables, 120 native/FormSelect usage sites, and 23 bespoke AppSelect usage sites. The earlier rough count of 92 included two shared components whose filenames end in `page.tsx`.
- [Per-route coverage and review candidates](ui-audit-route-inventory.md) are recorded separately.
- Browser coverage: Products, Contacts, Inventory, Purchasing, POS, Hospital, Accounting, Settings, Reports, and the missing-page fallback.
- Viewports: **1440 × 1000** and **390 × 844**, using headless Chrome.
- **25 snapshots**, including the product editor, category manager, price history, and mobile navigation.
- All tested snapshots finished with **zero axe violations** for the selected WCAG A/AA rules, zero captured runtime errors, and no detected page-level horizontal overflow.
- Fixtures are synthetic. Products/contacts/settings have sample data; operational lists are mostly empty. POS is tested with no available terminal, and Reports with failed report requests. Successful checkout, populated analytics, complex clinical records, real permissions, real invoices, and external payment integrations are **not** validated by these fixtures.
- Screenshots were manually inspected for the product catalogue, price-history dialog, and mobile POS. Screenshot capture/automated scanning of other routes is not equivalent to a detailed visual review.

Artifacts are generated under `/tmp/superstore-ui-audit-results/`: `results.json`, `source-inventory.json`, `lint-summary.json`, and named screenshots. They contain synthetic test data and are temporary, not deployment artifacts.

## Fixed in this pass

| Area | Finding | Change |
| --- | --- | --- |
| Typography | An unlayered font reset overrode component font utilities | Move the reset into the base layer; use the system UI font stack |
| Visual hierarchy | Repeating workspace grid and tinted header competed with content | Quiet workspace background and white application header |
| Contrast | Muted text, teal buttons, and active navigation failed contrast checks | Stronger accent/text colors and readable muted copy on light surfaces |
| Tables | Global `display: block` interfered with native table sizing | Restore native tables; retain scrolling on enclosing regions |
| Dialog sizing | Global rules stretched overlays across the workspace | Restore each dialog’s intended width; add safe legacy-overlay scrolling |
| Product dialogs | Missing native modality, focus containment, and Escape handling | Shared native Dialog for product edit/import, categories, price history, and receipt voiding |
| Form dropdowns | FormSelect synthesized incomplete change events and lost native behavior | Forward native select props/ref, validation, submission, option groups, disabled state, and mobile picker behavior |
| Searchable dropdowns | Missing keyboard navigation/dismissal and unconstrained menu edges | Keyboard opening, option navigation, Escape/focus restoration, viewport clamping, and dialog-local portals |
| Product feedback | Save/import/category errors could sit behind the modal | Render feedback inside the active dialog |
| Price history | Historical and current prices could be confused | Use product-master values for the current-price summary; distinct read-only history entries, formatted amounts, loading, retry, and empty states |
| Category preservation | A category absent from active options could change on an unrelated edit | Preserve the product’s current category as an available option |
| Mobile navigation | Closed sidebar remained in keyboard order | Hide inactive mobile navigation; focus containment, Escape, focus restoration, and background inertness when open |
| Shared navigation | No skip link; workspace indicator looked clickable without an action | Add skip link, current-page announcements, and a non-interactive workspace indicator |
| Notifications | Popup could overflow and was awkward to dismiss | Viewport-bounded scrolling, outside-click/Escape dismissal, expanded state |
| Labels | Several filters, checkboxes, pagination and settings controls lacked names | Label the browser-confirmed controls in Products, Contacts, Inventory, POS, Reports, and Settings |
| Access/loading failures | Network failure could look like permission denial; route fallback was generic | Retryable access-verification state, announced loading, dedicated page-error and 404 screens |
| Toasts | Errors expired quickly; reading time and close targets were limited | Persistent error toasts, pause auto-dismiss on hover/focus, timer cleanup, larger close buttons |

The changes do not alter purchasing price calculations, API permissions, or inventory activation rules.

## Remaining priorities

### P1 — Complete before a UI-wide release sign-off

1. **Migrate legacy dialogs workflow by workflow.** The source scan still finds **76 fixed-overlay declarations**, concentrated in POS, Purchasing, Pharmacy, Accounting, and clinical workflows. This is a count of declarations, not confirmed unique dialogs or confirmed accessibility failures. Audit naming, tab containment, Escape, unsaved-change handling, busy-state dismissal, scroll position, and inline errors. Do not mechanically replace every overlay: several are workspaces or nested workflows.
2. **Unify the remaining custom form controls.** AppSelect still uses a hidden form value; its `required` prop communicates semantics but does not itself enforce native constraint validation. Purchasing also has a separate dropdown-upgrade wrapper. Prefer FormSelect for ordinary fields; verify required, reset, disabled, keyboard, and FormData behavior for each searchable field.
3. **Resolve the lint backlog.** The latest source/config/script lint run reports **60 errors and 47 warnings**. Existing effect/state patterns account for many errors. Comparison against the committed code confirms the shell’s two errors and permission gate’s one error predate this pass; FormSelect’s error and AppSelect’s two warnings are resolved. Address the remainder with behavior-preserving changes and regression tests; do not disable rules globally.
4. **Test complete workflows with approved staging accounts and fixtures.** Cover owner/cashier/clinical/patient/platform roles; successful and rejected saves; purchase receipt and pricing modes; void/refund; stock transfers; patient and prescription forms; expiry warnings; and failed/slow network requests.
5. **Finish accessible labels and error announcements on untested routes.** The source inventory marks **246 controls for review**. These are heuristic candidates, not 246 confirmed defects: composed labels, option renderers and dynamic content require manual verification.

### P2 — Finish the visual and interaction standard

1. **Improve task density on mobile.** Several screens put long introductions and summary cards before the primary task. Mobile POS totals/actions remain far below the search area in the empty-terminal state. Test compact headings and sticky task actions with actual cashiers.
2. **Standardize page and form widths intentionally.** A legacy global rule still expands many page containers to 1440px. Review compact configuration forms separately from operational tables instead of applying one width everywhere.
3. **Replace native browser prompts.** The inventory finds **14 alert/confirm/prompt calls** across clinical, pharmacy, accounting and patient workflows. Use named confirmation dialogs with action-specific consequences and recoverable errors.
4. **Unify data presentation.** Make currency, tenant timezone, decimal precision, missing values, source labels, status badges, and table alignment consistent across modules. Do not infer a price delta when the API does not supply the prior value.
5. **Complete the state matrix.** Validate populated, empty, filtered-empty, loading, stale, unauthorized, offline, error, retry, saving and success states, especially Reports, Laboratory, Pharmacy, Patient Portal and Platform screens.
6. **Expand accessibility/device checks.** Test keyboard-only use, screen readers, 200%/400% zoom, 320px width, landscape phones, tablets, reduced motion, long names, large datasets, and alternate tenant colors. The default palette passes the sampled checks; arbitrary tenant colors are not guaranteed to pass.
7. **Make regressions visible in CI.** The supplied scripts provide a repeatable starting point. Add a maintained fixture server, pinned browser tooling, full workflow tests, screenshot review, and failure thresholds before treating them as a release gate.

## Repeat the checks

Run from `frontend/`:

```sh
npm run typecheck
npm run build
npm run lint
node scripts/ui-source-audit.mjs
```

For browser checks, start the local application on port 3015 in another terminal:

```sh
npm run dev -- --port 3015
npm install --prefix /tmp/superstore-ui-audit --no-audit --no-fund playwright-core @axe-core/playwright
node scripts/ui-audit-browser.mjs
```

Browser tooling is installed outside the repository; application dependencies are unchanged. The script requires Chrome at `/usr/bin/google-chrome`, or `CHROME_PATH`. Optional variables: `UI_AUDIT_URL` (localhost only), `UI_AUDIT_TOOLS`, and `UI_AUDIT_OUTPUT`. API requests are intercepted; writes are rejected locally.

The browser script fails on interaction assertions, unexpected runtime errors, or the page-error fallback. It records accessibility findings for review; it is not yet an accessibility or visual-diff CI gate.
